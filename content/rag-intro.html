Introduction to Retrieval-Augmented Generation

Published: 2026-11-17 | Category: Technical Notes

What RAG is

Retrieval-augmented generation (RAG) supplies a language model with relevant external passages at answer time. Rather than relying only on information encoded in model parameters, a RAG application retrieves from a separately maintained collection and includes selected results in the generation prompt.

Typical flow

  1. Ingest: extract text and useful metadata from source documents.
  2. Chunk and index: divide documents into passages, create an embedding for each, and store the vectors with passage text and metadata.
  3. Retrieve: embed the user's query and find relevant passages, often using vector similarity, keyword search, or a hybrid approach.
  4. Generate: provide the question and selected passages to the language model, asking it to answer from that context and identify supporting sources.

Illustrative query-time code

The functions below represent application-specific embedding, search, and model APIs. A production system should preserve source metadata with each result so the answer can cite the retrieved material. 

def answer_question(question, embed, vector_store, generate):
    query_vector = embed(question)
    passages = vector_store.search(query_vector, top_k=4)

    context = "\n\n".join(
        f"[{item.metadata['source']}] {item.text}"
        for item in passages
    )
    return generate(
        prompt=(
            "Answer using the supplied context. If it does not contain "
            "the answer, say so. Cite relevant source labels.\n\n"
            f"Context:\n{context}\n\nQuestion: {question}"
        )
    )

Practical considerations

Chunk size and overlap affect what information can be retrieved together; tune them for the document types and questions in your application. Increasing the number of retrieved passages can improve coverage but also add irrelevant context and consume more prompt space. RAG can make answers more grounded and sources easier to inspect, but it does not guarantee correctness: retrieval may miss evidence, and a model may still misinterpret or ignore it. Evaluate retrieval quality and answer quality separately using representative questions.
